HarmonyOS Tab 页面架构：两种模式对比

❌ 旧：独立页面 + Router 跳转

@Entry 页面 Index.ets
Tabs({ index: 0 })
Tab 1 → Text('占位')
↓ 点击底部 Tab 时 ↓
@ohos.router router.replaceUrl({ url: 'pages/Insight' })
整个页面被替换，Tab 动画消失
↓ 跳转到 ↓
@Entry 页面 Insight.ets
@Entry @Component struct InsightPage
自带 BottomTabBar（重复代码）
↓ 点其他 Tab 时 ↓
@ohos.router router.replaceUrl({ url: 'pages/Index' })
再跳回去，页面撕裂感
问题：
✗ 每个 Tab 页面是独立 @Entry，各自注册在 main_pages.json
✗ 切换靠 router.replaceUrl，有跳转延迟和闪烁
✗ 每个页面都得写一套 BottomTabBar，重复代码
✗ 无法滑动 Tab 切换，体验割裂
✗ 改底部 Tab 样式要改 N 个文件

✅ 新：嵌入组件 + 共享 Tabs

@Entry 页面（唯一） Index.ets
Tabs({ index: 0 })
↓ 内嵌 ↓
Tab 0 TabContent
Home()
@Component
Tab 1 TabContent
Insight()
@Component
Tab 2 TabContent
Focus()
@Component
Tab 3 TabContent
Mine()
@Component
BottomTabBar ← 只写 一次，Index 独有
优势：
✓ 只有 Index 是 @Entry，其他都是 @Component export struct
✓ main_pages.json 只注册 Index，子组件不注册
✓ 零 router 跳转，原生 Tabs 左右滑动 切换
✓ BottomTabBar 只写 一次，Tab 状态统一管理
✓ 改底部样式只改 Index 一个文件
✓ 子组件专注自己的业务逻辑，无跨页通信烦恼

文件改动
Insight.ets去 @Entry → 改为 export struct，删 router/BottomTabBar

main_pages.json删掉 "pages/Insight"
