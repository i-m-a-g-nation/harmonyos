# 《实习报告与实习日志》改写设计

## 1. 目标

以 `实习报告与实习日志.docx` 为版式参考，将其中“套牌车稽查系统”样例完整替换为当前 HarmonyOS“办公健康管理系统”的个人实习材料。报告以 Git 用户 `imagination <3158301763@qq.com>` 的实际工作为重点，突出“我的”模块的页面、组件、导航、模型、持久化与测试工作。

## 2. 输出与保留原则

- 原始 `实习报告与实习日志.docx` 保持不变。
- 新文件命名为 `办公健康管理系统-实习报告与实习日志-imagination.docx`。
- 保留原模板的封面、目录层级、四章结构、评阅表和评分表。
- 封面的姓名、学号、专业班级、指导教师等未知信息填写“待填写”。
- 删除原套牌车项目的正文、日志、图片、代码片段和人员信息，不保留与当前项目无关的事实。

## 3. 内容结构

### 3.1 生产实习概述

说明实习目的、时间、地点和计划。时间按当前项目提交记录整理为 2026 年 7 月 15 日至 7 月 23 日；地点填写“校内项目实训 / 待填写”，避免虚构企业或基地。

计划表使用九个自然日，覆盖：

1. 项目与资源熟悉、界面资源整理；
2. “我的”首页及二级页面框架；
3. 帮助与反馈页面；
4. 系统隐私、设备、数据、健康设置和个人资料页面；
5. 个人资料持久化与应用壳层解耦；
6. 模块边界梳理和主机测试；
7. 界面回归与文档整理；
8. 构建验证、问题复盘与改进；
9. 软件设计文档和项目总结。

### 3.2 生产实习内容

项目章节包括：

- 项目来源与背景；
- 办公健康场景和课题目标；
- 功能与非功能需求；
- `entry`、`feature_focus`、`shared` 模块结构；
- 首页、洞察、专注、“我的”四个一级功能；
- “我的”模块的页面、组件、模型、Service、Repository 和 Preferences 链路；
- 七个二级页面及导航深度上报；
- 测试、构建结果和当前功能边界；
- 项目总结与收获。

报告明确区分已实现能力与原型能力：反馈提交、设备配对、数据导出/清理及部分设置尚未连接真实服务，不描述为已经成功完成。

### 3.3 实习收获及总结

围绕 ArkTS/ArkUI、模块边界、单向事件流、导航、持久化、主机测试、团队协作和工程表达展开。避免沿用原样例中的人工智能车型识别、YOLO、CNN、KNN 等内容。

### 3.4 实习日志

编写 2026 年 7 月 15 日至 7 月 23 日共九篇日志。每篇包含：

- 当日实习内容；
- 专业技术收获；
- 遇到的问题与处理过程；
- 团队协作或职业规范体会；
- 下一步计划。

每篇不少于 300 个中文字符，任务内容以 Git 提交、当前代码和项目文档为依据；没有独立提交的日期用于记录设计、测试、回归和文档工作，不虚构外部活动。

## 4. 图表与视觉

- 复用模板的 A4 页面、页边距、标题层级、正文节奏、页眉页脚和评阅表样式。
- 使用当前项目的系统架构图、“我的”导航与持久化图、界面结构图替换样例图片。
- 计划表、功能表和评分表使用模板表格风格；正文不以表格承载长段落。
- 图片均带编号和说明，并明确界面图属于依据源码绘制的结构示意图。
- 控制分页，避免表格断裂、图片孤页、单行末页和大面积无意义留白。

## 5. 验证标准

- 原始模板 SHA-256 在处理前后保持一致。
- 新文档不包含“套牌车”“车辆特征”“YOLO”“KNN”“CNN”等样例项目残留。
- 报告包含四章、九篇日志、评阅表和评分表。
- 所有九篇日志均达到不少于 300 个中文字符。
- 文档包含项目架构、个人负责模块、测试结果和真实能力边界。
- 项目主机单元测试重新执行成功，结果写入报告。
- 对最终文档逐页检查，确认无文字截断、图片重叠、表格破损、页眉页脚错位或孤立末页。
